## Known bugs (open work)

### 1. `termination_by` functions don't compute (opaque)

**Symptom:** Functions annotated with `termination_by` (`strong_ind_impl`)
are marked `isOpaque: true` and evaluate to `VNeutral(NTop(name))` — stuck
forever. They type-check but don't reduce.

**Root cause:** The elaborator marks `termination_by` bindings opaque and
excludes them from recursive-group handling. No computable version is
auto-generated.

**Fix (planned for 0.8.2):** Fuel-based desugaring. For each
`fun f(args): T termination_by (x) = body`, generate two bindings:
1. `f_fuel(fuel: Nat, args): T` — structurally recursive on fuel, body
   rewritten to replace `f(e)` with `f_fuel(fuel_, e)`
2. `f(args): T = f_fuel x args` — public wrapper

The `_replaceSelfCalls` AST walker (recursive SExpr tree rewrite) is designed
and partially written but was reverted after the zero-fuel-branch type-checking
issue proved harder than expected. The zero case must produce a value of the
return type but has no base-case value available (Prop-returning functions
can't use `Nat` literals).

**Related:** `*_acc` functions in nat.doxa use manual accumulator recursion.
After fuel desugaring works, these can be rewritten to use `termination_by`.

### 2. Prop-into-Type restriction on `Lt`

**Symptom:** `strong_rec` cannot be built because `Lt` is Prop-sorted and
cannot eliminate into Type. Type-returning `termination_by` functions can't
use `strong_ind`.

**Fix direction:** Fuel-based recursion (item 1 above) bypasses this entirely.
Fuel is structural recursion on `Nat` — no `Lt` or `Acc` needed.

### 3. `_processImport` double-check

**Symptom:** The caller's `checkDeclResult` re-checks bindings already checked
by `_processImport` internally. Redundant work; harmless but wasteful.

**Status:** Not fixed. The ImportResolver eliminated this path for batch
pipelines but the REPL still uses `_processImport` directly.
