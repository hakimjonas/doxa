# Doxa — Session Handover (end of 0.8.1, 0.8.2 started)

## TL;DR

0.8.1 shipped and merged. 0.8.2 branch created for fuel desugaring.
The `_replaceSelfCalls` AST walker is proven correct. The zero-fuel-branch
type-checking is the remaining blocker: the zero case uses the original body,
which references the function name that is not in the fuel function's
elaboration scope.  Fix: add the original function name as a pre-binding
in the scratch env before elaborating `f_fuel`.

## Architecture: two complementary desugaring paths

```
termination_by (x)
       │
       ├── Fuel desugaring (0.8.2) ── makes functions computable
       │   ├ Any return sort (Type, Prop, SProp)
       │   ├ Structurally recursive on fuel (no Lt/Acc needed)
       │   └ Bypasses Prop-into-Type restriction
       │
       └── strong_ind desugaring (0.9.0) ── proves functions terminate
           ├ Prop-only return sort
           ├ Meta-obligations for Lt proofs (REPL interactive)
           └ Uses existing strong_ind in proofs.doxa
```

A future release may add a kernel-level `fix` primitive unifying both paths.

## Why not WellFounded.fix / Acc.rect

Doxa's recursor synthesis produces motives indexed by the full Acc
proof term. The induction hypothesis type contains `P R y (f y lt)`
— a 3-argument unreducible application — which the checker cannot
unify with the user's return type.  This is a kernel design
limitation, not an elaborator limitation.  Changing recursor
synthesis for all inductives is a distinct kernel project.

## Fuel desugaring status

### What works

`_replaceSelfCalls` — recursive SExpr tree walker that replaces
self-calls `f(e1, e2)` with `f_fuel(fuel-1, e1, e2)`. Handles all
SExpr kinds (SLamKind, SMatchKind, SAppKind, etc.).

### What's blocking

The fuel match `match fuel { case zero => kind.body; case succ f =>
rewrittenBody }` uses `kind.body` (original body) in the zero case.
The original body references the function name `f` (e.g.
`strong_ind_impl`), which is NOT in the scratch env used to elaborate
`f_fuel`.  The fix: add `f` as an opaque pre-binding in the scratch
env so the zero-case body can resolve it.

### Implementation plan

1. Add `_replaceSelfCalls` to elab.dart (code is ready, not committed)
2. Add `_desugarFuel` that:
   - Builds `wrapperBinders` first (needed for type-term)
   - Creates scratch env with BOTH `f` (opaque) and `f_fuel` (non-opaque) pre-bound
   - Elaborates `f_fuel` using `_elabFun(scratchEnv, ...)`
   - Elaborates wrapper `f` as a val calling `f_fuel x args...`
3. Wire into `_elabDecl` dispatch: for `SFunKind` with `terminationBy`,
   call `_desugarFuel` directly (before `_elabFunBlock`)
4. For mutual blocks (`SFunBlockKind` with a `termination_by` member):
   keep existing opaque behaviour for now, or add fuel pre-bindings
   and skip fuel bindings in the guarded loop

### Known limitations

- Mutual blocks require either stdlib restructuring or additional
  `_elabFunBlock` changes (fuel pre-bindings + guarded-loop skip).
- `strong_ind_impl` in proofs.doxa is in a mutual block with
  `strong_ind_impl_help`.  Can be restructured by parameterising the
  helper to receive the induction function explicitly, breaking the
  mutual dependency.
