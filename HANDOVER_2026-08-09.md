# Doxa — Session Handover (fuel desugaring landed, 0.8.2 ready)

## TL;DR

Fuel desugaring for single-function `termination_by` is implemented and all
checks pass.  `fun f(args): T termination_by (x) = body` now produces two
computable bindings (`f_fuel` structurally recursive on fuel, `f` wrapper
calling `f_fuel x args`).  Functions type-check and compute immediately.

The LSP handler's `id: Object?` bug (crashed on IntelliJ/PyCharm string-typed
request ids) is fixed.  The LSP id passes through as-is (int, String, or null)
without casting, matching the JSON-RPC 2.0 / LSP 3.17 spec.

`strong_ind_impl` / `strong_ind_impl_help` restructured: the helper receives
the induction function as an explicit parameter, breaking the mutual dependency.
`strong_ind_impl` is now a standalone `termination_by (n)` function handled by
fuel desugaring. `strong_ind` (the public wrapper) is computable.

A pre-existing parser limitation was diagnosed: Doxa identifiers do not accept
the `'` character (`n'` is lexed as `n` + stray `'`). The `_` suffix convention
(`n_`, `k_`) is the Doxa idiom. Systemic diagnostic improvement for invalid
identifier characters is deferred (a rumil-level concern, not a Doxa one).

Roadmap restructured: all feature work now ships in 0.8.x (0.8.3 strong_ind
desugaring, 0.8.4 well-founded defs, 0.8.5 infinite primes + LSP proof
state, 0.8.6 edges). 0.9.x becomes a refinement-only track. See
`docs/RELEASE_0_8_PLAN.md` for the detailed plan.

Test counts: kernel 456, tooling 520.  All stdlib files type-check.

## Architecture: two complementary desugaring paths

```
termination_by (x)
       │
       ├── Fuel desugaring (0.8.2) ── makes functions computable  ✓ DONE
       │   ├ Any return sort (Type, Prop, SProp)
       │   ├ Structurally recursive on fuel (no Lt/Acc needed)
       │   └ Bypasses Prop-into-Type restriction
       │
       └── strong_ind desugaring (0.9.0) ── proves functions terminate
           ├ Prop-only return sort
           ├ Meta-obligations for Lt proofs (REPL interactive)
           └ Uses existing strong_ind in proofs.doxa
```

## What shipped

### Fuel desugaring (`elab.dart`)
- `_replaceSelfCalls`: SExpr tree walker replacing self-calls `f(e1, e2)` with
  `f_fuel(_f, e1, e2)`.  Handles all 15 SExpr kinds with shadow tracking.
- `_desugarFuel`: generates two bindings — `f_fuel(fuel: Nat, args): T` with a
  fuel match (zero case = original body, succ case = rewritten body), and wrapper
  `f(args): T = f_fuel <tby> args`.  Returns a CorecursiveGroup so
  `checkDeclResult` handles self-referencing correctly.
- Dispatch in `_elabDecl`: single-param `termination_by` on `SFunKind` routes to
  `_desugarFuel` (with param validation).  Multi-param and mutual blocks fall
  through to existing opaque behaviour.
- `Nat` availability check: if `Nat` is not in scope (e.g. user forgot to import
  `nat.doxa`), throws `UnresolvedName` with the function's span before attempting
  fuel generation.

### LSP fix (`handler.dart`)
- `id` field on incoming messages now passes through as `Object?` (was `as int`
  cast).  Matches the LSP 3.17 / JSON-RPC 2.0 spec: id can be int, String, or null.
- Removed duplicate `import 'package:doxa/doxa.dart'`.

## Next: 0.8.3 — strong_ind desugaring

Per `docs/RELEASE_0_8_PLAN.md`, 0.8.3 adds strong_ind desugaring for
Prop-returning `termination_by` functions. The elaborator wraps the body
in a `strong_ind` call, replaces self-calls with induction hypothesis calls
plus meta-obligations for Lt proofs, and the REPL presents these
interactively. See the plan document for the four-step implementation.

## Deferred

- **Mutual block fuel desugaring**: no remaining stdlib use case.
- **Multi-parameter `termination_by`**: deferred to 0.8.4.
- **Parser diagnostic for stray characters** (`'`, `$`, etc.): a rumil-level
  concern, not specific to any one character.  Currently produces "Expected
  end of input" at a wrong line.  Fix as part of systemic rumil error
  reporting improvement, not as a one-off.
